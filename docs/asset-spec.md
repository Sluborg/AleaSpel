# Asset spec: character and wardrobe

Rules for every character and wardrobe image in AleaSpel. `scripts/art/validate.mjs` (run with
`npm run validate:art`, and in CI before every deploy) enforces the checkable parts.

## 1. The master

- `assets/source/base/master.png` is the fixed base for a single-pose dress-up system. Never
  modify, resize, crop or reposition it. Every wardrobe item is drawn to fit it.
- Origin: `assets/source/base/master-raw.png` (ChatGPT, green background, kept for reference).
  `scripts/art/key-master.mjs` removed the green only: character pixels kept, no resize, no move.
- Shipped copy: `public/assets/base/master.png`. It must be byte-identical to the source master
  (the validator checks this).
- Measured facts: canvas 1024x1536, character bbox x 263-760, y 125-1435 (125 px free above the
  head, 100 px below the feet), one solid component, no halo, 2.8% edge-antialiasing pixels.
- Base outfit: a plain light grey full-length unitard (wrists to ankles), barefoot, hair in a low
  bun. Facial features (eyes, brows, mouth) stay in the base for now. Face swaps (expressions,
  blinking) come later as separate `face_*` layers if needed.

## 2. Derived technical data

Generated by `node scripts/art/derive-base.mjs`, never edited by hand:

| File                                   | Shipped | Purpose                                         |
| -------------------------------------- | ------- | ----------------------------------------------- |
| `assets/source/base/mask.png`          | No      | Body silhouette (white where alpha >= 128)      |
| `assets/source/base/anchors.json`      | No      | Bbox and anchor points measured from the master |
| `public/assets/base/anchors.json`      | Yes     | Same data, for the game and the preview page    |
| `assets/source/base/debug-anchors.png` | No      | Review overlay: mask outline, bbox, anchor dots |

Anchor points (image pixels, `L`/`R` = image left/right, i.e. the character's right/left):
`headTop, eyeL, eyeR, faceCenter, chin, neck, neckline, shoulderL/R, armpitL/R, waist, waistL/R,
hipL/R, crotch, wristL/R, handL/R, fingertipsL/R, kneeL/R, ankleL/R, cuffL/R, footL/R, soleL/R`.
`neckline`, `wrist*` and `cuff*` are the unitard edges.

## 3. Canvas and registration

- Every wearable item is a **1024x1536 PNG with alpha**, containing only that item, drawn in the
  **exact position it sits on the master**. Stacking all layers at (0, 0) must give the dressed
  character. No offsets, no trimming, no scaling in code.
- Background fully transparent (alpha 0). No glow, drop shadow, outline effect or stray pixels.
- Colour stored straight (not premultiplied). Transparent pixels should have RGB 0.
- The item may cover parts of the body it hides (a sleeve over the arm); it must never contain
  body parts itself (no painted skin or hands inside a jacket file).

## 4. Layer order (back to front)

| Order | Layer       | Contents                                                      |
| ----- | ----------- | ------------------------------------------------------------- |
| 10    | hair_back   | Hair behind the head and body (long hair, ponytail backs)     |
| 20    | body        | The master (skin, face, base unitard, base bun)               |
| 30    | socks       | Socks, tights, leg warmers                                    |
| 40    | bottoms     | Shorts, skirts, trousers, leggings                            |
| 50    | onepiece    | Leotards, dresses, jumpsuits (one-piece outfits)              |
| 60    | tops        | T-shirts, tank tops, shirts, crop tops                        |
| 70    | outerwear   | Jackets, hoodies, cardigans, track tops                       |
| 80    | shoes       | Shoes, gymnastics slippers, boots                             |
| 90    | accessories | Hair bows, headbands, glasses, bags, medals, wristbands       |
| 100   | hair_front  | Hair in front of the face and shoulders (fringe, front locks) |

- One-piece outfits sit between bottoms and tops, so shorts can go under a leotard and a T-shirt
  over it.
- Socks sit directly on the body, under everything else, so trousers cover them and shoes cover
  their feet.
- A hairstyle is usually two files: `hair_back` and `hair_front` with the same id stem.
- Layer rows live in `src/data/wardrobe.json` (order, allowed region, tolerance). Adding a layer
  is a data row.

## 5. Folders and file names

```
public/assets/
  manifest.json
  base/master.png, base/anchors.json
  wardrobe/<category>/<id>.png           full-colour item
  wardrobe/<category>/<id>_tint.png      tintable item (grayscale, coloured in code)
  wardrobe/<category>/<id>_detail.png    optional untinted overlay for a tintable item
assets/source/                           source and derived files, not shipped
```

- `<category>` is one of: `hair_back, hair_front, socks, bottoms, onepiece, tops, outerwear,
shoes, accessories` (plus `base` for the master).
- `<id>`: snake_case, unique across the manifest, English, descriptive:
  `leotard_star_sleeveless`, `hair_ponytail_high` (back and front files share the stem).
- **Tintable items**: painted in light grey where white = the chosen colour, with shading in
  darker grey. The game multiplies by a colour (Phaser `setTint`, same maths as the preview), so
  one file gives every colour. Parts that must not change colour (a logo, glitter, buttons) go in
  the `_detail` file, drawn on top without tint.

## 6. Manifest

`public/assets/manifest.json`, one entry per file set:

```json
{
  "id": "leotard_star_sleeveless",
  "category": "onepiece",
  "layer": "onepiece",
  "file": "wardrobe/onepiece/leotard_star_sleeveless_tint.png",
  "tintable": true,
  "detail": "wardrobe/onepiece/leotard_star_sleeveless_detail.png",
  "license": "Project-owned, AI-generated for AleaSpel",
  "source": "ChatGPT image generation 2026-10-02, prompt in assets/source/prompts/leotards.md"
}
```

- Required: `id, category, layer, file, tintable, license, source`. Optional: `detail`.
- `layer` must match the category's layer in `src/data/wardrobe.json`.
- Game-facing data (Swedish name, unlock rule, default colour) goes in `src/data/*.ts` rows that
  reference the asset `id`, not in the manifest.

## 7. Validation rules (enforced by `npm run validate:art`)

Errors fail CI (no deploy); warnings are printed.

- Manifest: required fields present, `tintable` boolean, id snake_case and unique, file exists,
  category known, layer matches category, file name follows section 5.
- Canvas exactly 1024x1536, PNG with an alpha channel.
- Transparency: at least 30% fully transparent, no visible pixel on the canvas border, no stray
  islands smaller than 16 px. Warning if more than 2% of visible pixels are soft halo
  (semi-transparent and more than 3 px from solid pixels).
- Region: the item's visible bbox must lie inside its layer region, defined from anchors (for
  example shoes: from 120 px above the knees down; tops: from the chin to the knees).
- Silhouette: no visible pixel further outside the body mask than the layer tolerance (socks
  25 px, shoes 60 px, tops 120 px, bottoms 200 px, onepiece and outerwear 250 px, hair and
  accessories 400 px).
- Tintable files: average saturation must be low (grayscale); warning if the art is dark.
- Master: the shipped master equals the source master and has one clean component.

## 8. Checking new items

1. Add the PNG(s) and the manifest entry.
2. `npm run validate:art` locally, fix errors.
3. Push to `main`, then open `https://sluborg.github.io/AleaSpel/preview/` on the phone.
   Tick items, pick tint colours, switch backgrounds (Rutor/Mörk/Ljus/Grön) to spot halos, and
   toggle anchor points. The URL keeps the selection, so it can be shared.

## 9. Making items with an image generator (open)

Registration is the hard part: generators rarely keep the body pixel-identical. Options to test:

- Generate the item alone on flat green, using the master as a size and position template, then
  key the green in code (same method as `key-master.mjs`). Needs a manual alignment check in the
  preview.
- Generate the dressed character on green and subtract the master in code. Only works if the
  body pixels stay identical, which is not guaranteed.

A per-item extraction script is the next tooling step once the first real item is tried.
